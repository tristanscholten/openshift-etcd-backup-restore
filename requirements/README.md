# Requirements traceability

Status: as-built v0.2 candidate. Source: task contract and OCP 4.20 implementation contract. This document records implemented behavior, not production validation.

| ID | Requirement | Evidence | Verification |
|---|---|---|---|
| REQ-BACKUP-01 | After explicit installation confirmation, the role shall install a timer on only the nominated backup source at 00:00, 06:00, 12:00, and 18:00 UTC, with exact OCP 4.20.z and cluster identity loaded only from a root-only host EnvironmentFile. | role defaults/tasks/templates | syntax and rendered-template tests |
| REQ-BACKUP-02 | The runner shall promote only a vendor-successful snapshot/static-resource pair with metadata and SHA-256 values, validate every complete candidate before retention, then retain at most three valid managed sets. | runner script | fixture runner tests |
| REQ-BACKUP-03 | For a newly promoted HA set, the runner shall use only a root-only authorized healthy-cluster kubeconfig to capture allow-listed Node/Machine/CPMS identity fields, bind its 0600 inventory and digest to the exact non-circular snapshot/static-resource pair, and fail promotion without pruning existing valid sets if capture fails. SNO needs no HA inventory. | runner, capture helper, root-only EnvironmentFile/config | simulated runner capture-failure retention test; validator schema and hash tests |
| REQ-DISCOVERY-01 | Read-only discovery shall list only complete flat CronJob pairs whose root-private manifest, filenames, UUID/release, and SHA-256 values validate; it shall not read archive content. | `playbooks/list-backups.yml`; `scripts/discover_vendor_backup.py` | actual playbook fixture excludes a hash-corrupt pair |
| REQ-RESTORE-01 | Before destructive work, the restore playbook shall discover only valid flat CronJob pairs, display choices, require an explicit matching cluster UUID and exact OCP 4.20.z release, refuse CPMS/unsupported topology, and require a readable certificate kubeconfig plus executable absolute local `oc`. | `playbooks/restore.yml`; `scripts/discover_vendor_backup.py` | actual SNO/HA and fail-closed fixtures |
| REQ-RESTORE-02 | On SNO or exactly three non-CPMS control-plane hosts, one confirmed invocation shall fetch and revalidate one selected pair, copy and revalidate it on the recovery host, run vendor restore exactly once before API readiness, then execute the applicable documented stability flow. HA shall fence all hosts and only clear its quorum override after a successful stable wait; it shall not delete Machines. | restore playbook; pinned OCP 4.20 sources | actual local Ansible fixture; no OpenShift DR-lab proof |
| REQ-RESTORE-03 | The workflow shall obtain only one destructive confirmation after non-mutating discovery, write an in-progress checkpoint before host mutation, record failed recovery, refuse reruns, and write verified only after post-API stability. | restore playbook; README | actual failure and rerun fixtures |
| REQ-TEST-01 | A disposable local Podman etcd fixture shall snapshot, restore, and read back a marker key. | `tests/test_disposable_etcd_podman.sh` | executable local mechanics test; explicitly not OpenShift DR proof |
| REQ-UNINSTALL-01 | Uninstall shall require explicit confirmation, do nothing in check mode, remove only managed schedule/helpers from the nominated source, and never remove retained backup sets. | uninstall playbook | syntax and source guard tests |
| REQ-SAFETY-01 | The repository shall document its OCP 4.20-only and non-production-validation boundary. | docs | documentation inspection |
| REQ-CRONJOB-01 | The repository shall provide a self-contained `batch/v1` CronJob manifest that runs at `0 */6 * * *` UTC on one explicitly selected control-plane hostname, forbids overlap, uses bounded retry/runtime/history, and invokes the installed host vendor `cluster-backup.sh` through privileged `/host` chroot access with host networking but without host PID/IPC, an API token, or cluster-admin; its dedicated ClusterRole shall grant only `use` of the existing `privileged` SCC. | `manifests/etcd-backup-cronjob.yaml` | YAML fixture structure assertions and `oc apply --dry-run=client` |
| REQ-CRONJOB-02 | After a successful vendor invocation creates exactly one new complete snapshot/static-resource pair in `/home/core/etcd-backups`, the CronJob shall mark that pair and retain the newest three marked complete pairs; it shall not prune if vendor invocation fails or is partial, and it shall not delete unmarked files. | embedded CronJob shell | disposable stub-vendor fixture executes the exact extracted shell for success, rotation, partial failure, and unrelated-file preservation |
| REQ-RESTORE-BOUNDARY-01 | The repository shall state its supported OCP 4.20 SNO/three-host non-CPMS CronJob-pair recovery path, CPMS refusal, required inputs, and absence of real OpenShift DR-lab validation. | README | documentation inspection |
